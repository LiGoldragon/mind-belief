# Adopt an existing session without launching one

Use ordinary `Adopt` to bind a session that is already running. A declaration describes how a future session starts; a pane title describes what a person sees. Neither binds a running session. The Operator reports what is visible; the Flow Driver makes the authorized change.

Before acting, establish the intended address, the full native session ID and its harness, the Herdr session, pane and terminal ID, and the live foreground process. Check its start time, working directory and native session record: a reused PID, a similarly titled pane, a short FlowId or a remote-control URL is not the native identity. Reconcile any earlier attempt. Coordinate one executor. Serving v0 adoption can reserve an alias and perform normal address-local work; it is not a vacancy-only operation. Stop on a conflicting owner. Do not launch a second session to fix a routing problem.

## Two different kinds of failure

An address error such as `Unknown.Address` is about resolving the **recipient**. A send to an unavailable recipient is not evidence that its terminal or native conversation does not exist. Inspect the address spelling, declaration and current binding separately. Do not invent a new sender or resend an admitted or uncertain letter.

`Refused.Unidentified` on **Adopt** means Flow did not verify the proposed seat. Its fields are evidence, not a complete diagnosis. Read the serving journal for that exact address, pane and time. In the two cases below the journal said `RoleMismatch`: both panes had the right title and native UUID, but the Herdr agent's **name** was empty. Other causes of Unidentified require their own evidence. A different stored owner, wrong foreground or ambiguous native identity is not fixed by changing a label.

## Commands that registered the two Designers

On 26 November 2026, on Ouranos, the serving Flow code was `21b243b5`. I checked both original Claude sessions, their CLI session IDs, foreground process identities and terminal IDs. These were the ordinary requests:

```sh

flow 'Adopt.{ { Psyche ethos Fable } { default «w263:p1» } 9c3e1a46-80a6-44f9-b489-987773852ac9 }'
```

Both initially returned `Refused.Unidentified`. The stock issuer had nevertheless reserved `c85139` and `9c3e1a`. The corresponding `.flow-id` records contained the exact canonical native identities; they did **not** establish an address binding. I kept the reservations. Do not delete, reissue or infer a marker from a UUID prefix.

I checked the actual Herdr agent records (not only the terminal titles) and that the two intended agent names were unused. I named only these existing agents:

```sh

herdr --session default agent rename w262:p1 claude-c85139
herdr --session default agent get w262:p1

herdr --session default agent rename w263:p1 claude-9c3e1a
```

At each corrected seat I rechecked its agent name, full UUID, terminal ID and foreground process, then issued its original Adopt command once under the changed precondition. ## Verify the route at the level claimed

Use the initial **complete** snapshot from the dedicated ordinary stream `flow 'Observe.Metaflows'`. Match each exact address and Awake FlowId against the original Adopt receipt, issuer marker and native record. A snapshot can contain embedded newlines: reading one terminal line can give a false negative. In this incident the complete snapshot was recorded at 18:32:26 UTC, SHA-256 `a8e8099e2b625799a231667b86b748aa6e728daaca5ae751d6619ed37d0100de`. The operator's original receipts are under `flows/50fc8f/fable-nexus-native/` and `flows/50fc8f/fable-ethos-native/`: `w4wo-adopt.reply`, `c7un-route.reply`, `c7un-adopt.reply` and `c7un-bound.json`.

Registration is not message delivery. On the next real exchange keep the original request ID, sender, recipient and delivery cursor. Use `ObserveSends` for delivered/read evidence and correlate the recipient's actual answer to the same request and original sender. A queued receipt is not a reply. The Director reported a genuine design Question and Result on Nexus, `xwfq`. At the time of this record Ethos had the verified binding above, not a proven round trip. The adoption did not transfer any old request, notify either Designer or retire their predecessor. Do not send a test question to prove what genuine work can establish.

The commands and outcomes above describe serving v0 only. Private vacancy-checked adoption and any future Flow release have distinct contracts. Neither an isolated test nor a proposed repair is a deployed operation.
