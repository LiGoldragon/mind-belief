## Duties

The author makes the proposal directory or plain source and names its path to the visualizer. The visualizer draws the units and sends the drawn page to the bookmaker. The bookmaker publishes that page as given, at once. One available flow authorized for the job and equipped with native Artifact makes the single publish call. The responsible flow is the job’s stated responsibility address when it has one, or the actual commissioning flow otherwise. After publishing, send that flow the findings and relevant paths. If a tool prevents publication, send the exact failure and affected path after the attempt. The bookmaker owns that report. Give the checker and builder a job-local file containing `Off` through `BOOK_NOTICE_CONFIGURATION`; their diagnostics return to the bookmaker, which sends the one report. If no authorized native publisher is available, send it the prepared file path and exact blocker. A successful publication sends no notice to the commissioning flow; the module copies stay as the author made them; the manifest records the actual drawing model. A redo of a page he has not commented on replaces the same edition; a page he has commented on stays as published, and its redo is a new book. The builder uses one stylesheet. The bookmaker runs editorial checks after publication; a fault in the rendering is fixed in the builder or the figure grammar.

## A proposal into modules is a directory

A proposal or a review of pattern modules is a directory, one proposal and one page: a manifest and the edited copies of the modules it changes, made with `book-tools`.

```sh
book-tools copy DIRECTORY vision:pattern-modules:0 ... --title PRESENTATION_NAME --creator MODEL [--kind Review]  # each module as it stands on origin main, into DIRECTORY/<repository>/<path>, its revision recorded
book-tools new DIRECTORY REPOSITORY vision:fresh:0   # an empty copy of a module that does not exist yet
book-tools remove DIRECTORY vision:old:0             # a module named as removed
book-tools replace COPY OLD NEW                      # one exact, unique replacement; OLD and NEW are files, - for standard input
```

The writer edits the copies by its editing tools or by `book-tools replace`, which reads neither the module nor the copy again and refuses an old text that is absent or occurs twice. The directory is the proposal.

`book-tools` writes the manifest, `manifest.datom`, one datom, `Manifest.{ Title Kind Creator Option<Drawer> Entries }`, its entries in the order he reads the modules:

```datom
Manifest.{ «Pages.1» Proposal Fable Some.Sonnet
  [ Changed.{ «psyche-belief» «vision/book/0.md» «77d34db1462120c4206214a3a5428b4c817c8623» }
    New.{ «mind-belief» «knowledge/example/0.md» }
    Removed.{ «psyche-belief» «vision/example/0.md» «77d34db1462120c4206214a3a5428b4c817c8623» } ] }
```

The Presentation name is a PascalCase expression and its revision, such as `WhereAVectorIsRead.1`. The Creator is the model that made the proposal, set by `--creator MODEL`. The drawing step records its own model with `book-tools drawer DIRECTORY MODEL`. From these fields the builder places the name above `Created by Fable. Drawn by Sonnet.` when those models did the work. An undrawn draft has `None` and gives the creator alone. The post-publication check reports a missing drawer.

The builder makes the page from the directory: each module whole, under its identity, such as `{ Vision pattern-modules 0 }`, compared with the module at its recorded revision, every change marked in place by the marks of the presentation module, a new module whole as added and a removed module whole as removed. Lines that leave one copy and stand in another copy of the same proposal show once as moved. Its section headers contain just those identities, and its body shows the module lines with their change marks. Author comments and the why file stay with the source.

```sh
book-tools drawer DIRECTORY MODEL   # record the model returned by the drawing step
book-check /abs/DIRECTORY           # report findings after publication
book-build DIRECTORY OUT.html       # builds the page
book-tools source DIRECTORY         # prints the source the builder reads, where the figures are numbered
```

The lander runs `book-tools land DIRECTORY`: for each copy it reads the module as it stands now on origin main. Where the module has not moved since the recorded revision, the copy is what lands; where it has, the difference between the copy and the recorded revision is applied to the module as it stands. A part that does not apply refuses the whole landing, naming the module, and goes back to the author unforced; a new module that already stands, and the removal of a module that changed, are refused the same way.

## A plain source

A presentation that changes no module, an account among them, has a plain draft: its Presentation line and title, then its signature with the creator. The visualizer adds the drawing model to the signature of the page it hands to the publisher.

The Markdown source grammar for older books is in the makeshift-tools README and checker.

## The page

An Ethos fence that designs what ethos-zero does not know yet is marked tentative by its info string, `ethos sketch`: it is highlighted as Ethos and never checked by ethos-zero. The post-publication check reads the other Ethos fences.

The builder gives every figure the page's colours: each stroke, arrowhead, label and dark fill becomes the page text colour, each light fill the page surface, and both follow the reader's light or dark setting, whatever colours the SVG was drawn in. An Illustrator therefore draws in black on white. Only code is monospace: a code line wider than the screen scrolls inside its box, with a shade at the edge where code is hidden. A titled page that carries a change opens with the builder's key to its colours: added, removed and moved, each as a light proposed shade beside a dark landed one, and an excerpt and a module as they stand.
