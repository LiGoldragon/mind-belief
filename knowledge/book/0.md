## Duties

The author makes the proposal directory, or writes the plain source, and names its path to the bookmaker. The bookmaker has one Illustrator draw every Mermaid figure of the book as vector graphics in one run, under any margin, added, removed or unchanged; builds the page with the repository builder; and publishes it. Only the bookmaker publishes. The flow that ordered the book is told nothing when the page is published, since Psyche core Fable checks the pages himself. Every refusal of the checker or the builder, and any step that goes otherwise, the bookmaker Sends at once, in its exact words with the path, to Psyche core Opus, and takes the next book; the source and the directory stay as the author made them. A redo of a page he has not commented on replaces the same edition; a page he has commented on stays as published, and its redo is a new book. The builder's checker and its one stylesheet guarantee the page; a fault found on a published page is fixed in the builder or the figure grammar.

## A proposal into modules is a directory

A proposal or a review of belief modules is a directory, one proposal and one page: a manifest and the edited copies of the modules it changes, made with `book-tools`.

```sh
book-tools copy DIRECTORY vision:belief-modules:0 ... --title TITLE --creator MODEL [--kind Review]  # each module as it stands on origin main, into DIRECTORY/<repository>/<path>, its revision recorded
book-tools new DIRECTORY REPOSITORY vision:fresh:0   # an empty copy of a module that does not exist yet
book-tools remove DIRECTORY vision:old:0             # a module named as removed
book-tools replace COPY OLD NEW                      # one exact, unique replacement; OLD and NEW are files, - for standard input
```

The writer edits the copies by its editing tools or by `book-tools replace`, which reads neither the module nor the copy again and refuses an old text that is absent or occurs twice. The directory is the proposal.

`book-tools` writes the manifest, `manifest.datom`, one datom, `Manifest.{ Title Kind Creator Entries }`, its entries in the order he reads the modules:

```datom
Manifest.{ «Pages.1» Proposal Fable
  [ Changed.{ «psyche-belief» «vision/book/0.md» «77d34db1462120c4206214a3a5428b4c817c8623» }
    New.{ «mind-belief» «knowledge/example/0.md» }
    Removed.{ «psyche-belief» «vision/example/0.md» «77d34db1462120c4206214a3a5428b4c817c8623» } ] }
```

The Creator is the model that made the proposal, set by `--creator MODEL` on `copy`, `new` or `remove`, required when the directory is new, and shown as `Created by <Model>.` under the title; the checker refuses a manifest without one. The publisher is given the directory, and the manifest is its list of modules.

The builder makes the page from the directory: each module whole, under its name, `vision:belief-modules:0`, compared with the module at its recorded revision, every change marked in place by the marks of the presentation module, a new module whole as added and a removed module whole as removed. Lines that leave one copy and stand in another copy of the same proposal show once as moved. The page has no proposal numbers and no titles of its own, and its why stays in the why file beside the directory.

```sh
book-check /abs/DIRECTORY           # checks the directory
book-build DIRECTORY OUT.html       # builds the page
book-tools source DIRECTORY         # prints the source the builder reads, where the figures are numbered
```

The lander runs `book-tools land DIRECTORY`: for each copy it reads the module as it stands now on origin main. Where the module has not moved since the recorded revision, the copy is what lands; where it has, the difference between the copy and the recorded revision is applied to the module as it stands. A part that does not apply refuses the whole landing, naming the module, and goes back to the author unforced; a new module that already stands, and the removal of a module that changed, are refused the same way.

## A plain source

A presentation that changes no module, an account among them, is a plain source: its Presentation line and its title, then its subtitle line, the creator alone, `Created by <Model>.` such as `Created by Fable.`; the checker refuses anything else on that line (`subtitle-not-creator`).

Pages already published in the older source form, lines marked `+` and `-` under `### Proposal N` headings, still build; that grammar is in makeshift-tools, its `README.md` and `book-check.clj`.

## The page

An Ethos fence that designs what ethos-zero does not know yet is marked tentative by its info string, `ethos sketch`: it is highlighted as Ethos and never checked by ethos-zero. Every other Ethos fence is checked.

The builder gives every figure the page's colours: each stroke, arrowhead, label and dark fill becomes the page text colour, each light fill the page surface, and both follow the reader's light or dark setting, whatever colours the SVG was drawn in. An Illustrator therefore draws in black on white. Only code is monospace: a code line wider than the screen scrolls inside its box, with a shade at the edge where code is hidden. A titled page that carries a change opens with the builder's key to its colours: added, removed and moved, each as a light proposed shade beside a dark landed one, and an excerpt and a module as they stand.
