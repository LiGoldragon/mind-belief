## A reference checkout under /git

A shallow reference checkout lives at `/git/<host>/<owner>/<name>`. zoekt indexes every checkout's HEAD there (knowledge:search:0). Active development uses the repository's single plain-named checkout at `~/Code/<repo>`, on `main`, as knowledge:development:0 says.

## A shallow fetch

A repository fetched for reference or development is fetched shallow: the last commit alone, with no history. History is deepened only when a task needs it.

For a reference checkout:

```sh
git clone --depth 1 https://github.com/<owner>/<name> /git/github.com/<owner>/<name>
git -C /git/github.com/<owner>/<name> fetch --depth 1 origin main   # brought up to date, still shallow
git -C /git/github.com/<owner>/<name> fetch --deepen 50             # more history, when a task needs it
git -C /git/github.com/<owner>/<name> rev-parse --is-shallow-repository
```

## A tag made at the remote

A tag is created at the remote, through the forge's API; no checkout is needed. The commit is named in full.

```sh
sha=$(gh api repos/<owner>/<name>/git/refs/heads/main --jq .object.sha)
gh api repos/<owner>/<name>/git/refs -f ref=refs/tags/<tag> -f sha="$sha"
```

## Removing duplicate checkouts

Keep a duplicate checkout with uncommitted changes. Before removing a clean duplicate, push commits that are on no remote branch to a branch named after the checkout directory. Remove a linked worktree with `git worktree remove`. Keep the repository's plain-named checkout on `main`.
