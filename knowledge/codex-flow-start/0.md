# Starting a Codex flow

Every Codex address has a context watcher until Flow receives reliable Codex context readings through the Harness Nexus.

1. Before launching a new address, put its full `{ Aspect topic Model }` in `criomosHome.codexContextWatch.addresses` in the CriomOS-home profile. Check that its Codex session directory belongs to the configured launcher home or an explicitly declared migration home. Use the model policy in `criomosHome.codexContextWatch.modelPolicies`: it names the effective window and the refresh and escalation thresholds in input tokens for Sol, Astra, Luna or Terra.
2. Have Field activate the declaration. Confirm that `codex-refresh-watch-Aspect-topic-Model.service` is enabled and running for the address. A watcher waiting for the first rollout is ready for launch.
3. Launch the address through Flow. Before assigning work, check the watcher’s journal for `following <flow ID>` and the refresh and escalation thresholds it read for that flow. On a refresh the same watcher follows the new rollout and flow ID. A launcher change that moves the Codex home updates the watcher declaration in the same change.

The watcher follows completed rollout records. When Codex reports a smaller effective window than the configured window, it scales both thresholds down in proportion. A reminder counts as delivered when Flow reports `Delivered` or `Read`. The flow writes its handover and asks Flow for its own refresh.
